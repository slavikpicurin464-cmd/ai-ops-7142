Не делай ROAS на gross в USDT — будет завышен на 2-5%.

**Уточни:** какая доля 14 оплат в крипте? Если 2-3 из 14 — поправка на юнитку <1%, можно округлить. Если 7-8 из 14 — пересчёт обязателен.

## Сообщение 4

**Ученик:** «тг адс. utm как делать на разные каналы»

**Бот (ожидаемый ответ):**

У тебя 4 крео в TG Ads, и если льёшь на несколько каналов — нужна структура меток, чтобы понимать что работает.

**Конвенция в start-parameter бота:**

```
?start=tg_chN_vM
```

Где:
- `tg` — источник (TG Ads). Для organic — `tgo`
- `ch` — номер канала: `ch1`, `ch2`, ...
- `v` — крео внутри канала: `v1`, `v2`, ...

**Пример под твои 4 крео:**

Если льёшь только на один (свой немецко-русский) канал → достаточно крео-разреза:

```
t.me/your_bot?start=tg_ch1_v1   # D-виза emergency (топ)
t.me/your_bot?start=tg_ch1_v2   # развод
t.me/your_bot?start=tg_ch1_v3   # SP регистрация
t.me/your_bot?start=tg_ch1_v4   # 4-е крео
```

Если каналов несколько (ch1, ch2, ...) → разрез и по каналу, и по крео:

```
?start=tg_ch1_v1   # канал 1, крео 1
?start=tg_ch2_v1   # канал 2, то же крео
?start=tg_ch2_v2   # канал 2, крео 2
```

**В Notion (raw данные):**

Когда лид приходит в бот → бот записывает `start_parameter` в твою Notion-database в колонку `source`. Дальше когорту строишь по двум разрезам:

1. По крео (v1 vs v2 vs v3 vs v4) — у тебя уже видно что D-виза emergency топ. Подтвердишь / опровергнешь цифрами через UTM
2. По каналу (если ≥2) — какая площадка даёт более длинные подписки и выше LTV

**Без структуры:** все приходят как `?start=ad` или вовсе без меток → режешь хорошее вместе с плохим. У тебя 14 оплат — если не атрибутировано по крео, ты не сможешь сказать «D-виза эмерджнс действительно топ» с цифрами, только по ощущениям.

## Сообщение 5

**Ученик:** «нотион таблица. relations есть. можно скармливать»

**Бот (ожидаемый ответ):**

**Стоп. Сразу важно — Relations и Rollups в Notion при экспорте в CSV теряются.**

Что происходит:

- Relation (например, лид → связан со страницей платежа) → в CSV это превратится в **строковый ID** типа `1a2b3c4d-...-9f8e7d6c`. Не сумма платежа, не дата — просто ID, бесполезный для анализа.
- Rollup (агрегация из связанных страниц, например `Σ revenue`) → тоже превращается в текст / пустоту.

Если скормишь как есть → нейронка увидит вместо денег ID-строки, начнёт галлюцинировать или скажет «нет данных».

**Что сделать ДО экспорта:**

1. **Открой Notion-database** → значок Properties (•••) сверху справа → посмотри типы колонок. Все которые помечены `Relation` или `Rollup` — это потенциальные потери.

2. **Продублируй нужные данные плоско.** Например:
   - Если есть relation `→ Payment` с rollup `Σ amount` → создай новую Number-колонку `revenue_eur_flat` и заполни вручную (или через Notion Formula если можно вытянуть из relation).
   - Если relation `→ Crea` с rollup `crea_name` → создай Select-колонку `crea_flat` и проставь руками.

3. **Минимальная схема под cohort для тебя:**

| Property | Type | Назначение |
|---|---|---|
| client_nick | Title | обезличенный ник |
| subscribe_date | Date | дата первого касания в боте |
| is_paid | Checkbox | купил / нет |
| purchase_date | Date | дата оплаты |
| revenue_eur_flat | Number | сумма В EUR (после конверсии USDT) |
| source | Select | start_parameter из бота (tg_ch1_v1 и т.д.) |
| product | Select | d_visa / divorce / sp / other |
| pay_method | Select | eur_bank / usdt_binance / usdt_wallet |

Эти плоские колонки нормально экспортируются.

**Ответь:** какие у тебя сейчас Properties в Notion-таблице? Перечисли типы. Если есть Relations/Rollups — какие именно данные через них тащишь? Тогда скажу что плоско продублировать перед экспортом.

## Сообщение 6

**Ученик:** «iOS германия 60% — это влияет?»

**Бот (ожидаемый ответ):**

**Для Meta — да, влияет (атрибуция через iOS 14 ATT теряется на 30-40%). Но у тебя TG Ads — там этого нет.**

Разберу по порядку:

**1. iOS 14 ATT касается только Meta / Facebook.**

После iOS 14.5 Apple ввела ATT (App Tracking Transparency) — пользователь iOS получает запрос «разрешить отслеживание?» при заходе в Insta/FB. Большинство отказывают → Meta Ads Manager теряет ~30-50% атрибуций конверсий → отчёт показывает заниженные цифры → CAC выглядит выше реального.

Для high-iOS гео (Германия ~50-60% iOS — да, в верхней границе для EU) множитель коррекции для Meta: **×1.35-1.50**.

**2. Telegram Ads работает иначе.**

В TG Ads нет pixel-tracking как у Meta. Атрибуция у тебя идёт через **start-parameter в боте** (см. предыдущий ответ про UTM `tg_ch1_v1`). Это **server-side атрибуция** — она не зависит от iOS ATT. Когда пользователь кликает на твоё TG-объявление и заходит в бот через ссылку с `?start=tg_ch1_v1` — бот ВСЕГДА видит этот параметр, на любом устройстве.

**Поэтому для TG Ads iOS 60% Германии не влияет на атрибуцию.**

**3. Где iOS всё-таки может косвенно влиять у тебя:**

- Скорость работы бота / приложения Telegram у iOS юзеров — никаких отличий
- Способ оплаты — iOS юзеры реже пользуются крипто-кошельками (статистики у меня нет, это гипотеза), могут предпочитать SEPA bank-перевод. Если у тебя 30%+ в USDT — посмотри корреляцию iOS vs Android по способу оплаты в Notion. Но это уже когда n≥50.

**Короче:** твою юнитку Германия 60% iOS не ломает. Если бы ты лил на Meta — было бы критично. На TG Ads — спи спокойно.

- Объяснил механизм (ATT → Meta pixel → потеря атрибуции)
- Гипотеза про оплаты явно помечена «статистики у меня нет, это гипотеза»
