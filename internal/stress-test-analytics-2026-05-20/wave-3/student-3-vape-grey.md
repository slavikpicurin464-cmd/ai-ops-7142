## Запрос 1 — «Telegram Ads — основной канал. Cohort анализ»

### Что я обязан сделать до расчёта (Шаг 0 cohort-анализа)

Перед тем как считать когорты по TG Ads — отвечаю на 4 проверочных вопроса:

**1. Есть ли cohort-таблица в формате `client_id` + `subscribe_date` + `purchase_date` + `revenue`?**

В кейсе у меня агрегаты: 240 заказов из TG, 24% retention 90д, AOV $42. Это **не cohort-таблица, а сводные метрики.** Реальный когортный анализ невозможен без построчных данных по каждому покупателю.

Что нужно от клиента:
```
client_id | first_order_date | last_order_date | total_orders | total_revenue_usd | utm_source
client_001 | 2026-02-20      | 2026-03-15      | 2            | 84                | tg_ch1_v2
client_002 | 2026-02-22      | NULL            | 1            | 38                | tg_ch3_v1
...
```

Без этого — стоп, не делаю cohort. Запрашиваю выгрузку из бота / CRM.

**2. Есть ли разбивка spend по неделям/месяцам с привязкой к TG-каналам?**

Сейчас известен только общий бюджет $4,500 за 90 дней. Без разбивки spend по конкретным TG-каналам и неделям cohort ROI не считается — будет «общий бюджет / 320 заказов» = средняя по больнице.

**3. Что значит «retention 24% за 90 дней»?**

Здесь критическая развилка:
- (а) 24% клиентов сделали ≥1 повторный заказ в первые 90 дней с момента первой покупки
- (б) 24% клиентов вернулись в окне 60-90 дней с первой покупки
- (в) 24% всех заказов = повторные

Это три разные метрики, не интерпретирую самостоятельно. Уточняю у клиента/у себя в данных.

**4. Разделены ли холодный трафик (TG Ads → канал/бот) и retargeting (повторные продажи существующим)?**

При смешении CR искажается в 2-3 раза. Vape с retention 24% означает что значительная часть «продаж» это повторные — их не должно быть в cohort acquisition.

### Фикс 5 + 19 — UTM-конвенция для multi-channel TG Ads

Vape в TG — это типичный multi-channel: льёшь на 5-15 разных каналов (vape-тематика, lifestyle мужской KZ, тех-обзоры, и т.д.). Без структуры start-параметра режешь хорошее вместе с плохим.

**Обязательная структура start-параметра:**

```
?start=src_chN_vM_geoX
```

Где:
- `src` — `tg` для TG Ads (или `tgo` для TG organic)
- `ch` — номер канала: `ch1`, `ch2`, ..., `chN`
- `v` — крео: `v1`, `v2`, `v3`
- `geoX` — гео-разрез: `kz` или `uz` (важно для vape — два рынка)

**Пример для VapeStop:**

```
?start=tg_ch1_v1_kz   # vape-канал KZ, крео 1
?start=tg_ch1_v2_kz   # vape-канал KZ, крео 2
?start=tg_ch3_v1_uz   # lifestyle-канал UZ, крео 1
?start=tg_ch5_v2_kz   # тех-обзоры KZ
```

В CRM/Notion/Sheets записывать `start` в колонку `source` для каждого клиента. Дальше cohort строится по трём разрезам:

1. По каналу (`ch1` vs `ch2` vs ...) — какой канал даёт более долгие подписки / выше retention / выше LTV
2. По крео внутри канала (`ch1_v1` vs `ch1_v2`) — какой текст работает в этой тематической аудитории
3. По гео (`kz` vs `uz`) — какой рынок даёт лучшую экономику

**Дополнительно — колонка `channel_topic` в CRM:**

| ch | topic | geo |
|---|---|---|
| ch1 | vape_pure | kz |
| ch2 | lifestyle_male | kz |
| ch3 | tech_reviews | uz |
| ch4 | crypto_male | kz/uz |
| ch5 | gaming | uz |

Это даст ответ не только «какой канал», но «какая тематика конвертит лучше». Часто оказывается что vape-pure канал даёт CR 8-10%, а lifestyle 2-3% — но lifestyle дешевле на CPM, и итоговая CPA может быть похожа. Без разреза не увидишь.

### Когортная таблица — формат после сбора данных

Когда соберу UTM правильно, через 90 дней (один полный retention-цикл) построю:

| cohort_week | tg_channel | подписалось_в_бота | купили_30д | купили_60д | купили_90д | retention_90д | Σ_revenue_90д_USD |
|---|---|---|---|---|---|---|---|
| 2026-W08 | ch1 (vape KZ) | n=? | ? | ? | ? | ?% | ? |
| 2026-W08 | ch3 (tech UZ) | n=? | ? | ? | ? | ?% | ? |
| ... | ... | ... | ... | ... | ... | ... | ... |

Окна для vape (ECOM с retention): 7 / 30 / 60 / 90 / 180 дней.

Vape — это не классический ECOM_IMPULSE (где retention=0), это **ECOM_RECURRENT** — vape liquid заканчивается за 2-4 недели, клиент возвращается. Поэтому окна 30/60/90/180 более релевантны чем 360/540.

**Сразу применяю правило n<100 (Фикс 8):**

- Если cohort-канал содержит **<100 подписчиков** в неделе — пометка «n=XX, малая выборка, выводы предварительные»
- Если **<50** — «выводы носят характер гипотез, не решений»
- Если **<30** — «статистический шум, не делать выводов»

При spend $4,500 / 90 дней / 5-10 TG-каналов = $50-90 spend на канал на месяц. На таких объёмах большинство канал-cohort срезов будут n<50, многие n<30. Это значит — анализирую агрегатно (все каналы вместе как baseline), а индивидуальные каналы только для **направления гипотезы, не для решения «режем ch4».**

### Что выдаю клиенту прямо сейчас (до сбора правильных данных)

Не выдумываю когорты которых нет. Честно:

```
Cohort-анализ TG Ads запросил у клиента/собрал из CRM:
1. Сырьё по покупателям (client_id + first_order + покупки + UTM)
2. Spend по TG-каналам по неделям
3. Уточнение что значит «retention 24%» 

До сбора этих данных cohort не делаю — иначе галлюцинация.

Что делаем сейчас:
а) Внедряю UTM-конвенцию start=tg_chN_vM_geoX немедленно (старые лиды без меток в когорту не попадут, новые попадут)
б) Завожу базовый Sheet «client_id / first_order / source / revenue» на новых клиентов
в) Через 30 дней — первая промежуточная картина по новым когортам
г) Через 90 дней — первая полноценная картина с retention 90д
```

## Запрос 2 — «Бенчмарки vape в СНГ?»

### Применяю Фикс 4 жёстко

Бенчмарков по vape СНГ у меня **нет**. Не в скиле reality-check-metrics, не в АНАЛИТИКА-LOGIKA.md, не в моей голове как «общеизвестных норм».

## Запрос 3 — «Малая выборка по UZ — 112 заказов. Как разрезать гео?»

### Применяю Фикс 8 (малая выборка) + Фикс 17 (мультигео ECOM разрез обязательно)

**Что у меня в кейсе:**

| Гео | Заказов | Доля | Выручка (при AOV $42) | Spend (если пропорционально 35% от $4,500) |
|---|---|---|---|---|
| KZ | 192 | 60% | $8,064 | ~$2,700 |
| UZ | 112 | 35% | $4,704 | ~$1,575 |
| Прочее | 16 | 5% | $672 | ~$225 |
| **Total** | **320** | **100%** | **$13,440** | **$4,500** |

Обратная проверка (Фикс 13/22): 192 + 112 + 16 = 320 ✓. 60% + 35% + 5% = 100% ✓. $8,064 + $4,704 + $672 = $13,440 ✓.

### Применение правила малой выборки к UZ

**n=112 для UZ — это формально >100**, то есть **попадает в зону «выводы делать можно, но с осторожностью»**. НЕ зона «статистический шум» (n<30) и не зона «выводы как гипотезы» (n<50).

Но это **агрегат за 90 дней**. Если разрезать дальше:
- UZ × месяц = ~37 заказов на месяц → каждый месяц как срез **n<50** = «гипотезы»
- UZ × месяц × канал (5 каналов) = ~7 заказов на канал-месяц → **n<30** = «не делать выводов»
- UZ × месяц × канал × крео (3 крео в канале) = ~2 заказа на крео-канал-месяц = **шум, бессмысленно**

**Вывод по разрезам UZ:**

| Разрез | n за 90д | Действие |
|---|---|---|
| UZ всего | 112 | Можно делать выводы по экономике (CPA, AOV, retention) |
| UZ × месяц | ~37 | Тренд можно смотреть, но решения по месяцу — нет |
| UZ × канал | ~22 (при 5 каналах) | Гипотезы про каналы, не решения |
| UZ × креатив | ~15-20 | Не делать выводов до n≥50 |
| UZ × канал × креатив | ~5-10 | Шум, бессмысленно |

### Применение Фикса 17 (мультигео ECOM)

Vape — это типичный multi-geo ECOM с разной экономикой по странам. KZ vs UZ обязательно разрезать по 5 пунктам:

**1. ROAS / CPA отдельно по гео**

Не агрегировать KZ+UZ в «общий ROAS» — экономика разная. Считать:

```
KZ:
- Spend ~$2,700 (пропорция)
- Orders: 192
- CPA: $14
- Revenue: $8,064
- ROAS: 2.99

UZ:
- Spend ~$1,575
- Orders: 112
- CPA: $14
- Revenue: $4,704
- ROAS: 2.99

[Внимание: spend по гео — пропорция-гипотеза. Если в TG Ads и FB реальный split не 60/35/5 — пересчитать с реальными цифрами из кабинетов.]
```

ROAS одинаковый — это подозрительно хороший признак или артефакт пропорционального дележа spend. **Нужен реальный split spend по гео из кабинетов**, не пропорция от заказов.

**2. AOV отдельно по гео**

Vape liquid в KZ и UZ может иметь разный средний чек:
- KZ — выше доход, AOV возможно $42-50
- UZ — ниже доход, AOV возможно $30-38

Если в кейсе AOV $42 — это **средневзвешенное.** Реальные AOV по гео могут расходиться на 30-40%. Нужны построчные данные.

**3. Retention отдельно по гео**

Retention 24% общий — но в KZ может быть 28%, в UZ 18% (или наоборот — UZ-аудитория более лояльна по дефициту альтернатив). Нужен разрез:

```
retention_kz_90d = повторных_клиентов_kz / новых_клиентов_kz_за_первые_90д
retention_uz_90d = повторных_клиентов_uz / новых_клиентов_uz_за_первые_90д
```

При n<50 повторных в UZ — это всё ещё «гипотеза». Но направление поймём.

**4. Логистика на гео отдельно**

В Узбекистан доставка из KZ (если ты в KZ-юрисдикции) часто $5-8/заказ при AOV $30-38 = **15-25% от чека уходит в логистику**. Это съедает маржу.

Применяю Фикс 15 — диапазон, не точка:

```
Логистика KZ внутри = [ГИПОТЕЗА: $1-3/заказ] = 3-7% от $42
Логистика KZ→UZ = [ГИПОТЕЗА: $3-7/заказ] = 8-19% от $35-42

→ Реальная маржа UZ ниже KZ на 5-15 п.п. при тех же продуктах
```

Уточняю у клиента.

**5. Платёжеспособность и валютные риски**

UZ — другая валюта (сом), курс волатильный. Если принимаешь оплату в USDT или сом — добавляешь Фикс 11 (одна валюта на анализ):
- В UZ цены могут устанавливаться в сом, конвертируешь в USD по средневзвешенному курсу за период
- Если курс упал на 5%+ за 90 дней — отдельная пометка «риск курсовой разницы»

### Что выдаю клиенту по разрезу гео

```
Гео-разрез vape KZ/UZ за 90д:

KZ (n=192, статистически уверенно):
  Spend: $? (нужен реальный split из кабинетов)
  CPA: $?
  AOV: $? (нужен фактический по гео)
  Retention 90д: ?% (нужен разрез)
  Логистика: [ГИПОТЕЗА: $1-3/заказ]
  Маржа после логистики: [ГИПОТЕЗА: 30-55%]
  → Решения по KZ можно принимать

UZ (n=112, малая выборка пограничная):
  Spend: $?
  CPA: $?
  AOV: $? (часто ниже KZ на 15-25%)
  Retention 90д: ?% — на n=112 первичная оценка, нужно ≥150 для уверенности
  Логистика: [ГИПОТЕЗА: $3-7/заказ — выше из-за междугороднего]
  Маржа после логистики: [ГИПОТЕЗА: 20-45% — ниже KZ]
  Курсовой риск: уточнить если выручка в сом
  → По UZ агрегату гипотезы можно, по разрезам внутри UZ (канал/крео) — нет до n≥50 в каждой ячейке

Прочее (n=16, шум):
  → Не делать выводов, объединить в KZ или UZ по логике гео или исключить
```

### Решение «масштабировать UZ или резать?»

С n=112 на 90 дней — **рано** принимать решение «резать UZ». Что делаю:

1. Не резать. Продолжаю лить с теми же UZ-каналами ещё 30-60 дней до n≥150-200.
2. Параллельно делаю экономический расчёт worst-case: если маржа UZ 20% (нижняя граница) и логистика $7 — выходит ли в плюс? Если нет на основе **юнит-экономики** — исключение до сбора n обосновано не статистикой, а математикой (см. правило-исключение в SKILL.md).
3. Внутри UZ не разрезаю на каналы для решений — только для гипотез.

## Запрос 4 — «Маржа vape примерная — рассчитай гипотезой»

### Применяю Фикс 15 — маржа всегда диапазон, не точка

Маржа vape клиентом **не дана явно**. Это значит — НЕ ставлю «35% [гипотеза, общеотраслевой бенчмарк]». Это галлюцинация.

**Делаю диапазон по 3 сценариям. Минимальный/средний/максимальный.**

### Декомпозиция маржи vape — что вычитается из выручки

Базовая структура для VapeStop:

```
AOV (средний чек): $42

Минус COGS (себестоимость товара): 
  [ГИПОТЕЗА: $15-25 в зависимости от поставщика]
  - Прямой Китай: $15-18
  - Реселлер РФ/UAE: $20-25
  - Локальный дистрибьютор: $22-28

Минус логистика клиенту:
  KZ внутри: [ГИПОТЕЗА: $1-3]
  KZ→UZ: [ГИПОТЕЗА: $3-7]
  Средневзвешенная (60% KZ + 35% UZ + 5% прочее): 
  ≈ 0.6×$2 + 0.35×$5 + 0.05×$5 = $1.2 + $1.75 + $0.25 = ~$3.2/заказ
  Диапазон: $2-5/заказ средневзвешенно

Минус эквайринг / приём платежа:
  Карта Visa/Mastercard: 2-3% = $0.84-1.26
  USDT/наличные: 0-1% = $0-0.42
  [ГИПОТЕЗА: $0.5-1.5/заказ]

Минус упаковка / расходники:
  [ГИПОТЕЗА: $0.5-1.5/заказ]

Минус возвраты / брак:
  [ГИПОТЕЗА: 5-15% от выручки — vape liquid возвращают редко, но устройства бывают браком]
  = $2-6/заказ

Минус налоги (если белая часть бизнеса):
  Серая часть может вообще не платить
  Белая часть: УСН/НДС зависит от страны
  [ГИПОТЕЗА: 0-12% от выручки] = $0-5/заказ
```

### Три сценария маржи

**Сценарий A — пессимистичный (Реселлер + дорогая логистика + возвраты + полные налоги):**

```
AOV $42
- COGS $25 (реселлер)
- Логистика $5 (mid mix)
- Эквайринг $1.5
- Упаковка $1.5
- Возвраты $6 (15%)
- Налоги $5 (12%)
= -$1 убыток на заказ

Маржа: -2% (отрицательная)
```

**Сценарий B — средний (Реселлер хороший + средняя логистика + средние возвраты + серая часть):**

```
- Логистика $3.5
- Эквайринг $1
- Упаковка $1
- Возвраты $3.5 (8%)
- Налоги $0 (серая)
= $13/заказ маржа

Маржа: 31%
```

**Сценарий C — оптимистичный (Прямой Китай + KZ-только логистика + низкие возвраты + полностью серая):**

```
AOV $42
- COGS $15
- Логистика $2
- Эквайринг $0.5
```

### Итог по марже

| Сценарий | Маржа % | Маржа $ на заказ | Условия |
|---|---|---|---|
| A пессимистичный | -2% | -$1 | Реселлер дорогой, высокая логистика, налоги |
| B средний | 31% | $13 | Реселлер хороший, средняя логистика, серая |
| C оптимистичный | 52% | $21.8 | Прямой Китай, локальная KZ, серая |

**Диапазон маржи: -2% до 52% — слишком широкий разлёт.**

Это значит — **обязательно уточняю у клиента, иначе вся юнит-экономика будет фантазией.** Конкретно нужно знать:

1. Поставщик: Китай прямой / реселлер / локальный?
2. Сплит логистики: какая доля KZ-внутри vs KZ→UZ vs UZ-внутри?
3. Уровень возвратов фактический (если CRM ведётся)
4. Налоговый режим: серая / белая / гибрид?
5. Эквайринг: какой % платежей через карту vs USDT/наличные?

### Применение маржи к юнит-экономике (по worst-case = Фикс 15 правило)

**Делаю расчёт по worst-case (B средний — не A, потому что A с убытком означает что клиент уже бы закрылся за 90 дней):**

```
Маржа (worst-case разумный): 31% = $13/заказ
LTV (упрощённо за 90д с retention 24%):
  = AOV × (1 + 0.24 × повторные_за_90д_avg) × маржа
  
[ГИПОТЕЗА: 0.24 retention означает 24% делают ≥1 повторный, в среднем 1.3 повторных на возвращающегося]
  = $42 × (1 + 0.24 × 1.3) × 0.31 = $42 × 1.31 × 0.31 = $17/клиент за 90д

CAC текущий:
  = $4,500 / новых клиентов
  Новые клиенты = 320 - повторные
  Повторные = retention × некий base, нужно уточнить
  [ГИПОТЕЗА: 320 заказов = ~250 уникальных клиентов, из них 60 сделали ≥1 повторный = retention 24%]
  → CAC = $4,500 / 250 = $18/новый клиент

LTV:CAC = $17 / $18 = 0.94

Maximum CAC = LTV × 0.8 = $17 × 0.8 = $13.6

→ Текущий CAC $18 выше Maximum CAC $13.6 → **реклама в минус на marginal basis при марже 31%**
```

**Sanity-check обратной формулой (Фикс 13/22):**

`LTV × маржа = max CPA × safety` → $42 × 1.31 × 0.31 = $17.05 потенциал. Max CAC при 0.8 safety = $13.6. Если бы CAC был $5 — LTV:CAC = 3.4, всё ок. Если бы CAC был $50 — LTV:CAC = 0.34, катастрофа. Текущий $18 → LTV:CAC = 0.94 — почти в ноль, без запаса.

Подставляю обратно: max CAC $13.6 × 1.25 (1/0.8) = $17 = LTV. Сходится ✓.

**Если маржа окажется 52% (оптимистично):**
```
LTV = $42 × 1.31 × 0.52 = $28.6
Max CAC = $28.6 × 0.8 = $22.9
LTV:CAC = $28.6 / $18 = 1.59 — окупается, без запаса
```

**Если маржа окажется -2% (катастрофа):**
```
Реклама в минус по математике, при любом CAC.
Решение основано на юнит-экономике, не на статистике.
Срочно менять поставщика или цены.
```

### Вердикт по марже

```
Маржа vape [ГИПОТЕЗА: 25-50%, диапазон 3 сценариев A/B/C] — УТОЧНИТЬ У КЛИЕНТА.

При среднем сценарии B (маржа 31%):
  LTV ~$17/клиент за 90д
  CAC текущий ~$18 → LTV:CAC = 0.94 (хуже окупаемости)
  Maximum допустимый CAC = $13.6
  
Действие до уточнения маржи:
  1. Не масштабировать бюджет — текущий CAC выше потолка при средней марже
  2. Срочно получить от клиента: COGS, реальная логистика, возвраты, налоги
  3. Если фактическая маржа окажется в нижней части (25-30%) — нужно либо снизить CAC, либо поднять AOV/LTV (cross-sell, upsell на устройства, recurring подписка на liquid)
  4. Если ближе к 45-50% — есть запас для масштабирования, но всё равно проверить на UZ отдельно (там маржа ниже из-за логистики)
```
