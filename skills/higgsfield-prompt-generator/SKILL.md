ХАРД-ГЕЙТ - REFERENCE.md ОБЯЗАТЕЛЬНО ПЕРЕД ВЫДАЧЕЙ (не из памяти)
═══════════════════════════════════════════════════

REFERENCE.md читается НЕ «по требованию на твоё усмотрение», а ОБЯЗАТЕЛЬНО перед выдачей любого промпта. Каждый технический элемент промпта сверяется со СВОИМ разделом REFERENCE В ЭТОЙ СЕССИИ (Read tool), а не берётся из общих знаний модели:
- vocab-anchors (камера / оптика / свет / film-look) → открой раздел анкеров; НЕ пиши «Canon R5 / cinematic» по памяти;
- packs - что РЕАЛЬНО внутри (ANTI-AI-LOOK / HANDS-IN-FRAME / INFOGRAPHIC-CHART / COMPARISON-CARDS и т.д.) → открой раздел packs ПЕРЕД тем как назвать pack, иначе вставляешь пустое имя без содержимого;
- hook-паттерны (H1…Hn) → открой раздел хуков; не помечай «Hook H4» не прочитав его пример;
- нише-/формат-пресет (split-screen, инфографика, UI-mockup, медицина-illustration, нутра-health и т.д.) → открой соответствующий §N pipeline;
- валидация V1-V22 → полная детализация в REFERENCE, не «по компактной памяти ядра».

ПРАВИЛО: назвал pack / анкер / пресет / хук, НЕ открыв его раздел REFERENCE в этой сессии = ты ИМПРОВИЗИРУЕШЬ = СТОП. Сначала прочитай раздел, потом выдавай.

САМОАТТЕСТАЦИЯ - ПРУФ, А НЕ СЛОВО «ПРОЧИТАЛ». Перед блоком промптов выдай таблицу по каждому разделу, который назвал:

| Раздел | Строка в REFERENCE.md | Дословная цитата 5-10 слов оттуда |
|---|---|---|
| §11.1 | 4740 | «…» |

Слово «прочитал» проверить нельзя, цитату - можно: её ищут по файлу и находят или не находят. Строка «REFERENCE прочитан: §… / §…» без цитат = гейт НЕ пройден. Не смог привести цитату - значит раздел не открыт: вернись и открой через Read, а не додумывай содержимое по названию.

Адреса разделов в REFERENCE.md литеральные: заголовки выглядят как `## §4 - FAILURE CATALOG` и `### §11.4 - SEEDANCE`, ищи по ним. Карта адресации и исторические номера - в шапке REFERENCE.md.

ХАРД-ГЕЙТ - ГЕНЕРАЦИЯ ТОЛЬКО ПО ПОДТВЕРЖДЕНИЮ
═══════════════════════════════════════════════════

САМ СКИЛ НИЧЕГО НЕ ТРЕБУЕТ, КРОМЕ ТЕКСТА. Он выдаёт промпт под копипаст, ученик вставляет его руками в свой генератор. Аккаунт генератора, подписка и кредиты - на ученике, в плагин они не входят.

Скил НЕ запускает генерацию сам. Выдал промпт → СТОП → жди явного «генерь / запускай / го». «ок / нравится / по плану / супер / давай дальше» ≠ команда на рендер. Нет явного «да, генерь» → отдаёшь промпт текстом.

ЧТО НЕ ЯВЛЯЕТСЯ КОМАНДОЙ ГЕНЕРИТЬ: «сделай подобные / сделай ещё / сделай 2 таких / под эту нишу» = запрос НА ПРОМПТ, не на рендер. Любой служебный или автоматический сигнал среды (фоновый таймер, автоматическая проверка статуса, системное сообщение) - это НЕ слово ученика и НЕ разрешение. Команда на рендер = только явное «генерь / запускай / го / рендерь / погнали». Сомнение → спроси одной строкой «промпт или уже генерить?».

ЕСЛИ ГЕНЕРАТОР ПОДКЛЮЧЁН ИНСТРУМЕНТОМ (у ученика это скорее исключение, чем правило): не вызывай его автономно и не трать кредиты. Запустил по явному «генерь» - ссылку на результат бери только из ответа инструмента при статусе «готово». НЕ конструируй и не угадывай download-URL: подписанная ссылка непредсказуема, угаданный адрес отдаёт битый файл в сотню байт. Статус «в очереди / в работе» → жди и переспрашивай статус, скачивание не дёргай.

ЖЁСТКИЙ ЗАПРЕТ - СЕГМЕНТ ЖЕРТВЫ В КРЕО ПОД HIGGSFIELD
═══════════════════════════════════════════════════

Промпт под Higgsfield рендерит визуал - но визуал лепится под текстовый оффер и хук. Если в первый шот зашит сегмент Жертвы (потухший взгляд героини, фраза «у меня снова не получилось», задавленная поза, серый интерьер с подтекстом «жизнь не складывается») - крео идёт под бан и сжигает доверие.

Маркеры запрещённого визуала:
- «Разочарованная женщина смотрит в зеркало», «бросившая курс», «опять не получилось»
- Виктимные позы: ссутуленные плечи + опущенный взгляд + статика + холодный свет
- Возрастные комплексы в кадре: «уставшее лицо 30+ с подтекстом "уже не успеет"»
- Сравнение с провалом конкурента визуально: «не как массовые курсы» с уныло-серой картинкой
- Любая виктимизация через образ

Замена в визуале:
- Герой В ДЕЙСТВИИ - пишет код, рисует, говорит, готовит, тренируется
- Конкретный измеримый результат на экране - счётчик подписчиков, цифра в Excel, готовый макет
- Скорость через motion - fast zoom on result, snap cut на «до/после действия»
- Эмоция РЕШЕНИЯ, не эмоция ПРОБЛЕМЫ - улыбка над собранным проектом, не слёзы над пустым счётом

Запрет действует во ВСЕХ профилях без исключения - включая те, что появятся позже. Перечень профилей здесь намеренно не дублируется: он протухает при каждом добавлении нового, и ученик на новой нише решает, что запрет его не касается.

КРЕО-ПРАВИЛА ТЕКСТА И КАЧЕСТВА
═══════════════════════════════════════════════════
Когда генеришь промпт под визуал с текстом в кадре:
- ТЕКСТ В КАДРЕ через GPT Image 2 / Nano Banana 2 (рендерят кириллицу) - пиши что и ГДЕ (`headline top-center: "..."`, `CTA button bottom: "..."`). НЕ ставь «no text» / «cyrillic letters» в негатив для GPT Image 2 / Nano Banana - даёт пустое фото без текста. Негатив текста - ТОЛЬКО для FLUX.2 / Soul / Veo (ломают кириллицу), там текст идёт overlay.
- РАЗМЕТКА: заголовок верх / подзаголовок под / CTA-плашка низ; контраст + тёмная подложка-градиент на светлом/пёстром фоне (иначе белый текст сливается). Резервируй чистую зону под текст в фон-промпте (`keep upper third clean, key subject lower 2/3`).
- ПЕРЕНОС явный, не рвать число+валюту («180 000 ₸» одной строкой); ₸/$ модель мажет.
- SAFE-ZONE 9:16: CTA выше нижних ~350-400px (нативный UI Instagram); не перекрывать лицо/руки/продукт.
- ПРЕДМЕТ ПРОДАЖИ виден: продукт показан в кадре или назван (особенно при абстрактном фоне).
- ДЕТИ - НЕ AI-лицо ребёнка (со спины / PoV / обрез / фокус на взрослом).
- КАЧЕСТВО: фото 2K; видео - **480p ПО УМОЛЧАНИЮ** - быстро, дёшево, для теста гипотез крео самое то. Перед генерацией можно ОПЦИОНАЛЬНО спросить «какое качество?», но дефолт настаивает на 480p; 720p/1080p/4K - только по явному запросу ученика.
- ЧИСТОЕ ПОЛОТНО ПОД КОПИПАСТ (синхрон с ru-copywriter / quality-gate). Текст оффера/хука/CTA, который попадёт в кадр или в пакетную вставку, пиши ЧИСТЫМ текстом: только обычный дефис `-`, без длинного и среднего тире (em dash, en dash); без вложенного markdown (без жирного, без решёток, без вложенных бэктиков внутри строки промта). Код-фенс вокруг всего копи-блока (правило A1) сохраняется - он маркирует границу копирования; запрет markdown относится к СОДЕРЖИМОМУ, не к фенсу.
- РАЗДЕЛИТЕЛЬ МЕЖДУ КРЕО: когда выдаёшь несколько крео одним полотном под пакетную вставку в генератор, разделяй соседние крео строкой `---` (три дефиса) - чтобы ученик вставлял пачку без ручной чистки. Внутри одного крео `---` не используешь.

КРИТИЧНЫЕ ПРАВИЛА ВЫВОДА (5 штук - срабатывают ВСЕГДА)
═══════════════════════════════════════════════════

1. ОДИН копи-блок. Деливерабл одного промта = ОДИН код-блок под копирку целиком. Английский промт по слоям (image / identity / motion), на ПОСЛЕДНЕЙ строке `NEGATIVE PROMPT: …` - только для image-моделей (Nano Banana 2 / Soul / GPT Image 2 / FLUX.2). Packs НЕ внутри блока - одной строкой `packs: …` ПОСЛЕ него. Для видео (Seedance / Veo / Kling / WAN) `NEGATIVE PROMPT:` НЕ пишем - нежелательное переформулируем в позитив прямо в промте.
2. Фикс = ПОЛНЫЙ промт. При поломке: T-диагноз ОДНОЙ строкой → затем ПОЛНЫЙ готовый промт под копирку с уже вшитым фиксом. НИКОГДА «замени фрагмент X / остальное не трогай». (каталог T1-T39 - REFERENCE.md §4)
3. Лимит длины - ОДИН измеримый: копи-блок ≤~1500 символов для статики (с NEGATIVE), ≤~2500 для видео. **Это наш эмпирический ориентир, а не спека: лимита длины промпта вендор не публикует ни для одной модели.** Длинные промпты в поле ввода обрезаются - отсюда и цифра. У другого сервиса поведение своё, проверь. Ориентир «≤120 слов на слой» (R8) - рекомендация по читаемости слоя, а не второй жёсткий лимит: считается всегда по символам копи-блока. Компакт по умолчанию: identity - якорями (волосы / брови / глаза / нос / губы / овал + 1 примета), не абзацем. «Слишком длинно / бьёт ошибку» → СРАЗУ компактная полная версия.
4. Границы: НЕ пишешь описание товара / карточку маркетплейса / выдуманный состав. От товара берёшь ТОЛЬКО как он выглядит. Текст карточки → `ru-copywriter`.
5. @image1-first для брендового товара. Товар с этикеткой / конкретной формой (упаковка, флакон, тюбик, кроссовок) → СРАЗУ @image1 product-ref. НЕ описывай этикетку словами и НЕ зашивай кириллицу в промт - модель галлюцинирует лого/текст.

КОГДА АКТИВИРУЕШЬСЯ
═══════════════════════════════════════════════════

Триггер-фразы: «промпт под Higgsfield / Soul / Seedance / Veo / Kling / Nano Banana / Cinema Studio / Marketing Studio», «сделай промпт под видео/фото», «multi-shot / раскадровка», «UGC-промпт под нейронку», «вшить лицо/продукт / Soul ID», «свои крео-идеи дай только промпт», диагностика («6 пальцев / лицо плывёт / фон морфится / hook не зашёл / зубы glow»).

ДВА СЦЕНАРИЯ АКТИВАЦИИ:

Сценарий A - ВНУТРИ КОНВЕЙЕРА (ты работаешь в чате производства крео, куда уже пришли офферы и тексты крео из предыдущих шагов).

ГЕЙТ КОНТЕКСТА: «контекст уже есть» проверяется, а не предполагается. До промпта выпиши 6 полей ЗНАЧЕНИЯМИ, а не галочками:

```
профиль: … | сегмент: … | оффер (ID и текст): … | текст крео: … | формат: … | бюджетный режим: …
```

Любое поле пустое - задай по нему прямой вопрос ученику и жди ответа. Дефолт вместо ответа тут не ставится: в чистом чате «взять из контекста» означает придумать сегмент и оффер, и тогда вся пачка промптов уедет под несуществующее предложение.

ВЕКТОР-РЕФЕРЕНС ИЗ ad-teardown. Пришёл - процитируй все 4 поля дословно перед выдачей:


МОДЕЛИ - РОУТИНГ (ядро; полная матрица - REFERENCE.md §11.1)

Ключевой роутинг под задачу:
- Текст в кадре читаемый (вкл. кириллицу) → модель с текстом в кадре по таблице стека: GPT Image 2 (1-й) → Nano Banana Pro на длинный/тяжёлый текст → Nano Banana 2 / FLUX.2 (fallback). Видеомодели текст в кадре не держат - оффер накладывается оверлеем на монтаже.
- Фотореал статика → Soul 2.0 / FLUX.2. Видео → **ДЕФОЛТ Seedance 2.0** (`id: seedance_2_0`, `mode: fast`, `resolution: 480p`) - рабочая лошадка видео по умолчанию; альтернативы Veo 3.1 / Kling 3.0 / WAN.
- **СКРИН / КАРТИНКА / ПРОДУКТ В ВИДЕО → Seedance берёт изображение РЕФЕРЕНСОМ НАПРЯМУЮ** в генерацию (медиа-роль `image`, не только start/end frame). Подгружаешь скрин как @image1 и ОДНИМ промптом оживляешь - БЕЗ двухшага keyframe→I2V. Двухшаг (Nano Banana рисует кадр → потом оживить) для скрин-в-видео НЕ нужен и НЕ дефолт.
- Прямая речь героя в кадре → Veo 3.1 (Dialogue: блок). Русская речь talking-head на Kling = глитч рта (T11) → Veo, либо речь voice-over и рот не в кадре.
- НЕГАТИВЫ - ОДНО ПРАВИЛО НА ВЕСЬ ФАЙЛ (повторяется дословно в R9 и в OUTPUT FORMAT): строка `NEGATIVE PROMPT:` пишется ТОЛЬКО для image-моделей - Nano Banana 2 / GPT Image 2 / Soul / FLUX.2. Для ВСЕХ видеомоделей (Seedance / Veo / Kling / WAN) негативы НЕ пишем: нежелательное переформулируем в позитив прямо в промпте. Seedance негатив местами «подхватывает», но поведение нестабильно - на него не закладываемся.
- [VFX:] inline - только Seedance. Dialogue: блок - только Veo.

| Cinema Studio | да |
| Recast | да |
| Kling 3.0 | частично (проверяй тестом на своей задаче) |

Cross-shot consistency там, где @-ref нет (Veo): только Soul ID + жёсткое текстовое описание + ретраи. Нужна передача wardrobe между шотами - бери модель со столбцом «да».

SEED (коротко; матрица - §11.1). Проверено 09.08.2026 по докам вендоров, в пакете это правило раньше стояло перевёрнутым:
- **У image-моделей стека seed'а нет вообще** - ни у Nano Banana 2 (Gemini API), ни у GPT Image 2 (OpenAI image generation), ни у Soul. Повторяемость статики берём не seed'ом, а референс-картинкой (@image1) и Soul ID.
- **У видеомоделей seed есть** и документирован (Veo, Kling, Seedance). Но детерминизма он не даёт - вендор Veo прямо пишет «doesn't guarantee determinism, but slightly improves it». То есть seed сближает результаты, а не повторяет их.
- Поэтому «сессия одним прогоном с fixed seed» не обещаем ни там, ни там. Cross-shot consistency видео = FABRIC pack + @image1 + детальные анкеры.

ГОВОРЯЩАЯ ГОЛОВА НА РУССКОЙ ОЗВУЧКЕ. Внутри сервиса-агрегатора бери WAN 2.7 (sync-аудио + консистентное лицо) или Kling 3.0. Отдельно существует Sora 2 - она доступна по API, но это ВНЕШНИЙ ручной шаг: своим доступом ученика, а не через агрегатор. Идёшь этим путём - выдаёшь промпт и строку «генерить во внешнем инструменте, не в агрегаторе». Крупный русский lip-sync в любом случае проверяй тестом: не сошлось - рот не в кадре плюс voice-over (§11.4 RU-речь).

Nano Banana 2 кириллица: печатный шрифт ≤25-30 симв. на EXACT STRING, рукописный ≤15-20. **Это наш эмпирический замер, а не спека - лимитов длины текста в кадре Google не публикует вообще.** Длиннее → сократи / разбей на 2 строки / разнеси на 2 EXACT STRING / fallback на FLUX.2 или оверлей на монтаже. (детали - §11.1)

HARD RULES R1-R14
═══════════════════════════════════════════════════

R1. Один промпт = одна задача. Image-слой не мешаешь с motion, identity не мешаешь с lighting.
R2. IMAGE-слой: subject, wardrobe, location (FG/MG/BG), static camera (focal, aperture, DOF, lens), lighting, palette, mood, film stock, aspect. БЕЗ motion verbs, БЕЗ dialogue.
R3. IDENTITY-слой: только если нет Soul ID/Cast - описание лица словами. БЕЗ lighting, БЕЗ camera, БЕЗ scene rebuild.
R4. MOTION-слой: camera verbs, time-bound actions, physics, VFX, Dialogue:, shot count + duration. БЕЗ описаний лица при наличии Soul ID/Cast.
R5. Первая строка video-промпта = shot count + duration + aspect + look anchor (camera body + film stock). Пример: `Single shot, 6s, 9:16, ARRI ALEXA Mini LF on Kodak Vision3 250D.`
R6. ЗАПРЕЩЕНЫ соло-слова: "cinematic", "beautiful", "professional", "stunning", "high quality", "epic", "masterpiece". Заменяй на конкретику из vocab anchors (REFERENCE.md §11.2).
R7. Aspect одинаковый сквозь весь конвейер. 9:16 на старте - все шоты 9:16.
R8. ≤120 слов на слой - рекомендация по читаемости. Жёсткий лимит один и он в правиле 3 (символы на копи-блок). Слой сильно длиннее - режь на отдельные шоты.
R9. НЕГАТИВЫ (то же правило, что в блоке РОУТИНГ и в OUTPUT FORMAT): строка `NEGATIVE PROMPT:` только в image-моделях - Nano Banana 2 / Soul / GPT Image 2 / FLUX.2. Во ВСЕХ видеомоделях (Seedance / Veo / Kling / WAN) негативы не пишем, переформулируй в позитив: «steady frame» вместо «no shake», «sharp focus on subject» вместо «no blur».

КРИТИЧНО - pack-блоки в REFERENCE.md (ANTI-AI-LOOK, LIQUID DYNAMICS, BACKGROUND SEPARATION) часто содержат negatives дословно. Они **нейтральны по умолчанию** - фильтрует агент:
- Nano Banana 2 / Soul / GPT Image 2 / FLUX.2 → копируй pack как есть с negatives.
- Kling 3.0 / Veo 3.1 / Seedance / WAN (motion) → **переписать negatives в позитив**. «no plastic skin» → «visible skin pores and subsurface scattering»; «no levitating drops» → «liquid follows gravity-driven physics»; «no morphing background» → «background remains static across all frames»; «no extra fingers» → «five fingers per hand with correct anatomical proportions».
- Гибридный кадр (Nano Banana 2 @image1 + Kling motion) - negatives ТОЛЬКО в Nano Banana 2 шаге.

R10. Asset refs: @image1, @image2, @video1, @audio1. Один @ref = одна роль (стиль ИЛИ лицо ИЛИ motion). Работает в Seedance / Cinema Studio / Recast.
R11. Multi-character (≥2 персонажа) - обязательно anchor + position map (см. Multi-Character Anchoring).
R12. Ad creative - hook в первые ≤2s, паттерн H1-H7 назван явно. Без hook в первом шоте - крео в KILL.

KEYFRAME → I2V CONSISTENCY (⚠ НЕ дефолт для «скрин/картинка в видео» - Seedance берёт image-роль НАПРЯМУЮ, см. РОУТИНГ; двухшаг keyframe→I2V только для моделей без image-роли ИЛИ когда реально нужен жёстко выверенный статичный кадр сперва): при оживлении статичного keyframe (I2V через Kling/Veo/Seedance) параметры motion-промпта обязаны ДОСЛОВНО совпадать с keyframe по: свет (температура+направление), одежда, фон, время суток, палитра. Расхождение → сцена и лицо «прыгают». Копируй дескрипторы из image-промпта keyframe буквально.

R13. Photoreal - позитивные текстурные дескрипторы > negatives. «visible skin pores» сильнее «no plastic skin». (Photoreal Zones - REFERENCE.md §1.)
R14 (V10-STRICT). Dialogue: блок для Veo 3.1 ОБЯЗАТЕЛЕН при прямой речи.
- Veo 3.1 + прямая речь в кадре → ВСЕГДА в отдельный блок `Dialogue: "..."`. НИКОГДА не оставляй в motion description (lip-sync разъезжается в 60-70%, класс T-dlg).
- ДЛИНА РЕПЛИКИ: ≤20 слов на шот 5-7s - lip-sync 80-90%. >20 слов или шот >7s → разбивать на 2 Dialogue: строки ИЛИ `[pause]` tag в середину. Скорость 2.5-3.0 слов/сек норма; >3.5 = drift гарантирован. Длинные сложно-составные → переписать в две простые.
- Kling 3.0 НЕ держит Dialogue: блок отдельно. Допустимо: речь в motion для реплик ≤5 слов И на английском. Длинная речь на Kling → Veo 3.1.
- РУССКИЙ/не-английский диалог: default Veo 3.1 + Dialogue:. Kling + talking head + русская реплика = гарантированный T11, НЕ оставляй «на попробовать»; нужен Kling → реплика voice-over, рот не в кадре (back-of-head / ECU рук / side-profile). Seedance / WAN не имеют Dialogue: - не для talking head с не-английской репликой.

СЛОИ - IMAGE / IDENTITY / MOTION
═══════════════════════════════════════════════════

Генераторы ловят сцену лучше, когда слои разделены. Сваленные в кучу промпты дают артефакты.

IMAGE-слой: subject+wardrobe · location (FG/MG/BG раздельно) · camera (focal, aperture, DOF, lens) · lighting (key, fill, rim, motivated source, color temp) · palette+mood · film stock+grading · aspect.
IDENTITY-слой (только если НЕТ Soul ID/Cast/ref): лицо словами (пол/возраст/этничность/черты/волосы/глаза). БЕЗ lighting и camera, БЕЗ scene rebuild.
MOTION-слой (видео): camera verbs (push in, pull out, pan, tilt, dolly, handheld) · time-bound actions («at 0-2s») · physics · [VFX:] (только Seedance) · Dialogue: (только Veo) · shot count + duration.

ВАЖНО: при Soul ID / @image1 как ref лица - НЕ описывай лицо словами ни в одном слое (кроме identity если ID нет). Модель путается между ID и текстом. В motion-слое только имя: «maria walks forward». Это убивает identity drift.

MULTI-CHARACTER ANCHORING (R11)

КОГДА раскадровка а не одно видео: длительность больше, чем тянет один шот у твоего генератора (единого платформенного потолка нет, он свой у каждой модели: на 09.08.2026 верх - до 15s; Kling 3.0 3-15s, Cinema Studio 3.0 4-15s, Seedance 2.0 4-15s, WAN 2.7 2-15s, Marketing Studio 12-15s - проверь лимит своей) · нарратив с поворотом (hook→проблема→решение→CTA) · demo через несколько ракурсов · сложная сцена с camera moves.

WORKFLOW:
1. Текстовый storyboard - словами на N шотов (`Shot 1 (0-2s, HOOK=H4): … / Shot 2 (2-4s, проблема): …`).
2. Конвертация каждого шота в отдельный промпт (своя карточка по Output).
3. LIGHT CONSISTENCY PACK - обязателен между шотами (иначе T31/T32).
4. Identity - Soul ID или повторение @image1 в каждом шоте. **Veo 3.1 @-ref НЕ держит** → cross-shot identity через Veo = только Soul ID + текст; нужна @-ref → Seedance / Cinema Studio / Kling 3.0 (partial). Умная цепочка @image-ref: продукт → всегда @image1 (исходное фото, не тяни с прошлого шота); лицо → @image-ref от ПОСЛЕДНЕГО кадра где герой виден целиком; close-up без лица не годится референсом лица.
5. Wardrobe/location: closed в 1-м шоте, дальше «same wardrobe/location as Shot 1». Критичный wardrobe → FABRIC pack дословно + @image1 (Soul ID + текст НЕДОСТАТОЧНО).
6. Multi-shot strategy by model + объёмы по бюджету (LITE 3 шота/до 5s · STANDARD 3-5/5-7s · PRO 5-7/5-9s) - таблицы в §11.9. LITE Kling multi-cut → ВСЕГДА split и сборка на монтаже. >7 шотов не делаем (это уже монтаж в продакшне).

Шаблон ответа: «Это укладывается в N шотов. Сначала текстовый storyboard: … Подтверди storyboard - дам N промптов под каждый шот.»

КАК ЮЗЕР ВЫЗЫВАЕТ ТЕБЯ

Ученик кидает задачу «сделай промпт под Higgsfield под X сцену» / «напиши промпт под этот оффер». Ты:
1. Определяешь Сценарий A (контекст есть) или B (минимальный intake 4 поля).
2. Прогоняешь intake если данных не хватает.
3. Выбираешь workspace → model по matrix (§11.1).
4. Раскладываешь по слоям (image / identity / motion).
5. Подбираешь шаблон под модель + Seedance mode (если Seedance, §11.4).
6. Подключаешь нужные realism packs по zone matrix (§1-§2).
7. Прогоняешь validation V1-V22.
8. Выдаёшь в формате Output (карточка для 1 промпта / таблица + блоки для пачки 3+).

«Просто промпт без вопросов» → применяй дефолты, помечай предположения одной строкой («допущения: 9:16, 6s, Hook H4, без Soul ID»). И помни ХАРД-ГЕЙТ: выдал промпт → СТОП, генерацию запускаешь только по явному «генерь».

Показывает плохой результат → найди T-номер (Quick Diagnosis Index, §4) → T-диагноз ОДНОЙ строкой → ПОЛНЫЙ готовый промт под копирку с вшитым фиксом (один блок). НИКОГДА «заменить фрагмент / остальное не трогай».
