# Winner Variations

Ты разворачиваешь победившее крео в 5-8 вариаций и 1-2 диких эксперимента. Цель - выжать максимум из найденного выигрышного угла и параллельно подготовить замены до того как победитель устанет.

## Когда использовать

Срабатывает на этапе масштабирования и решений ПОСЛЕ закрытия этапа аналитики недели с решением SCALE по конкретному адсету. Это вход в следующий цикл - что запускаем в неделю N+1.

Также вызывайся когда ученик прямо просит:
- «вариации победителя по адсету X»
- «масштабирую крео X - дай 5 вариаций»
- «дикие эксперименты под победителя»
- «scale креатива»

НЕ подгружай если:
- По адсету нет решения SCALE (только KILL/HOLD) - для них вариации не делаются.
- Этап аналитики недели не закрыт - сначала диагностика, потом масштаб.
- Это первая итерация (нет факта по победителю) - сначала запускаем первичную пачку гипотез через `creative-brief-writer`.
- Победитель отработал больше 21 дня без обновления - это уже не масштаб, это замена, нужен новый цикл: офферы, подходы, производство крео.

## Что делает

Шаг 1. ВХОД-ГЕЙТ. Победитель предъявляется строкой из отчёта, а не словами.

Ученик пишет «у меня SCALE, CPL 6» - это не данные, это пересказ. До вариаций выпиши таблицей, СКОПИРОВАННОЙ из кабинета или отчёта:

| Адсет | Период (с-по) | Спенд | Целевое действие | Результатов, шт | Cost per result: план / факт | Frequency |

Плюс формат победителя (видео / товарная статика / Reels-импульс) и исходный промпт крео - сегмент, подход, формат, hook, body, CTA и остальные поля, по которым крео собиралось.

Метрику берёшь ту, по которой адсет реально выиграл: для лидгена это обычно CPL плюс hook rate / hold rate / CTR, для товарной статики и e-com - ROAS, CPP, CTR, доля заказов в рассрочку. Не натягивай CPL туда, где считается продажа.

СТОП-ПРАВИЛО: хотя бы одно поле не предъявлено - «данных по победителю нет, вариации не делаем», и список того, что нужно достать. Красивая таблица вариаций на пересказанных числах не отличается от честной, и в этом её опасность.

ПОРОГ, ДО КОТОРОГО ПОБЕДИТЕЛЯ НЕТ. Решение SCALE не принимается, пока не выполнены все три условия:
- результатов на адсете достаточно, чтобы разница по cost per result перестала быть разбросом. Ориентир: при 5-10 результатах отклонение в полтора-два раза - это норма шума, а не победа;
- срок крутки соответствует циклу сделки в нише (в импульсной товарке крео живёт неделю, в B2B срок крутки сам по себе не говорит ничего);
- спенд на адсет соизмерим с целевой ценой результата: если потрачено меньше нескольких целевых CPL/CPP, обсуждать нечего.

Данных не хватает - вердикт «ЖДЁМ ДАННЫХ»: пишешь, сколько ещё результатов или дней нужно, и вариации НЕ предлагаешь.

Шаг 2. Применяет правило одного параметра.

Меняешь ОДИН параметр за раз. Это нужно для чистой атрибуции - чтобы понять что именно влияет на метрику.

Какой набор параметров брать - смотри на формат победителя. Победитель видео - берёшь видео-набор. Победитель товарная статика (карточка, баннер, packshot) - берёшь набор для статики. Не смешивай наборы.

Набор для ВИДЕО - 5 параметров:

- hook - первые ≤2 секунды (звук, текст, визуал). Хук-окно единое по всему пакету: ≤2 секунды. 3-секундный video view - метрика Meta, не длина хука.
- actor - кто говорит (другой возраст / другой пол / другая локация / голос за кадром).
- format - UGC → Cinematic → Static → Reel → Carousel.
- duration - 6 / 15 / 30 / 60 секунд.
- bg - фон / локация съёмки (офис / дом / на улице / минимализм).

Набор для товарной СТАТИКИ - 5 параметров:

- ракурс/кроп - как снят товар (фронт / три четверти / деталь крупно / товар в руках / на модели).
- фон/подложка - белый / цветной / фактура / lifestyle-сцена / градиент.
- подача цены и рассрочки - есть / нет плашки, цена крупно / мелко, «0-0-12» вынесено вперёд / спрятано.
- модель / манекен / flat-lay - кто или что носит товар (живая модель / манекен / только товар / flat-lay раскладка).
- один товар / комплект - показываем одну позицию или собранный комплект / образ.

Набор для REELS-ИМПУЛЬСА / ECOM_IMPULSE - 5 параметров:

- hook - те же ≤2 секунды, но визуалом (текст-плашка, action-кадр, не «говорящая голова»).
- demo-angle - что и как показываем (action - товар в действии / reaction - реакция на товар / before-after - до и после / price-reveal - акцент на цене).
- trend-sound - звук с актуального тренда vs нейтральный фоновый vs голос-войсовер.
- price-display - плашка с ценой крупно / плашка мелко / без плашки совсем.
- CTA - свайп вверх / «в шапке профиля» / прямой клик в Shop / без явного CTA (товарный клик через тег).

В наборе ECOM_IMPULSE специально убраны actor и duration как оси.
- Actor не имеет смысла - на 15-секундном demo нет «говорящей головы», есть товар и руки / тело без лица.
- Duration не имеет смысла - Reels-импульс работает в коридоре 8-15 сек, шире не идёт, и тестировать 30 vs 60 = тестировать нерелевантные варианты.

Параметр «язык» - отдельная ось вариации для двуязычных рынков (RU / KZ / смешанный). Работает и для видео, и для статики, и для Reels-импульса. Это дешёвый и логичный A/B - текст в кадре и озвучка меняются, всё остальное держится как у победителя.

Не меняй два параметра одновременно даже если очень хочется. Иначе через 7 дней не поймёшь что сработало.

Шаг 3. Генерирует 5-8 вариаций по схеме нейминга.

Схема одна на все наборы: `{адсет}.v1.{N}-{код оси}`. Коды латиницей, чтобы имя читалось в Ads Manager одинаково у всех:

- видео-набор: `hook` / `actor` / `format` / `duration` / `bg`;
- товарная статика: `angle` (ракурс, кроп) / `bgr` (фон, подложка) / `price` (подача цены и рассрочки) / `model` (модель, манекен, flat-lay) / `set` (один товар или комплект);
- Reels-импульс: `hook` / `demo` (demo-angle) / `sound` (trend-sound) / `price` (price-display) / `cta`;
- ось языка в любом наборе: `lang`.

Пример: `SMARTPET_PREMCORM_STATIC_v1.v1.3-price`. Кириллицу в именах не используем - иначе половина адсетов будет `.v1.1-ракурс`, половина `.v1.1-angle`, и сводить их в отчёте нечем.

Можно делать по 2 вариации на параметр (v1.1a, v1.1b) если есть две сильные гипотезы внутри одного параметра. Тогда выйдет 8 строк.

Шаг 4. В колонке «Гипотеза» каждой вариации пишет, почему меняем этот параметр.

Гипотеза живёт ТОЛЬКО в колонке «Гипотеза». В колонках Body / Hook / CTA лежит текст самого объявления - то, что уйдёт в кабинет. Гипотеза, попавшая в Body text, уедет в тело объявления и открутится на аудиторию.

- v1.1-hook → «исходный hook „Понимаю каждое второе, улыбаюсь как дурочка" даёт hook rate 34%. Гипотеза - hook „Завтра созвон на английском - ты к нему готова?" может поднять до 40%+ потому что добавляет срочность».
- v1.2-actor → «исходный актёр - карьеристка 32 Алматы. Гипотеза - актёр-женщина 29 лет из Минска (та же боль, другая локация) даст лучше по BY-аудитории».
- и так далее.

Шаг 5. Опционально - 1-2 диких эксперимента.

Дикие эксперименты идут отдельно от 5-8 вариаций и не считаются как SCALE. Бюджет на них - 10% от НЕДЕЛЬНОГО бюджета на связку (одна база на весь скил, все примеры ниже считаются от неё же).

Дикие идеи для ВИДЕО-победителя:
- Длинный формат 60-120 секунд (vs 15-30 на победителе).
- Мем-формат с трендовым звуком.
- UGC от нетипичного для сегмента лица (мужчина-карьерист в женском сегменте, бабушка-предпринимательница).
- Странный hook - тишина первые 3 секунды, обратный отсчёт, чёрный экран с текстом.
- Формат без человеческого лица - анимация / motion graphics / только text на цветном фоне.

Дикие идеи для СТАТИКИ-победителя:
- 3D-рендер товара вместо фотосъёмки.
- Карусель-комплект - не один товар, а собранный образ / набор по слайдам.
- Инфографика размерной сетки или сравнения - вместо чистого packshot.

Каждый дикий маркируется `.exp1`, `.exp2`. Если зайдёт - переходит в обычные вариации в следующем цикле. Если не зайдёт - выкидываем без сожаления, на то и эксперимент.

Шаг 6. Финальная таблица - все поля исходного промпта крео + версия + гипотеза. Идёт прямо в таблицу гипотез крео (`04-creatives.md`) следующего цикла.

Шаг 7. СЧИТАЕТ, СКОЛЬКО ВАРИАЦИЙ ТЯНЕТ БЮДЖЕТ - до того, как назвать их число.

Порядок: сколько денег в неделю нужно ОДНОЙ вариации, чтобы она набрала минимум результатов из порога выше → сколько таких вариаций помещается в недельный бюджет. Получилось меньше пяти - так и пиши: «бюджет тянет N вариаций, больше делать нельзя». Делить бюджет поровну между 5-8 строками, когда каждой достаётся меньше минимума, - это способ через неделю снова принимать решение по шуму. Сокращай число вариаций, а не порцию каждой.

## Формат ответа

Один. Таблица вариаций с явной колонкой «Что меняем» - один параметр на строку.

Два. Гипотеза для каждой вариации привязана к фактическим данным победителя - hook rate, hold rate, CTR. Без «потому что я так думаю».

Три. Дикие эксперименты - отдельная таблица, не вмешаны в вариации.

Четыре. Финальное распределение бюджета на неделю - в строках, с процентами.

Пять. Если просят 5 вариаций - давай 5, не 8. Не натягивай объём.

## Quality-gate

Перед выдачей проверь:

- Каждая вариация двигает свою ОСЬ ОЩУТИМО, не косметически. «Тот же hook другими словами», «фон чуть светлее», «CTA с другим глаголом при той же механике» - это НЕ вариация, это дубль. Вариация = осмысленный сдвиг по оси (другой тип хука / другой типаж актёра / другой формат-носитель / другая ценовая подача), за которым стоит проверяемая гипотеза. 5 разных строк, которые на рендере дадут 5 почти одинаковых крео → переписывай. Цель - покрыть РАЗНЫЕ гипотезы, а не размножить победителя.
- В каждой вариации меняется РОВНО ОДИН параметр относительно победителя. Если изменилось два - переписывай. «Язык» (RU / KZ / смешанный) считается валидным одним параметром - менять язык, держа всё остальное как у победителя, это корректная вариация.
- Гипотеза стоит в колонке «Гипотеза», а не в Body text, и опирается на конкретную метрику победителя, не на «мне кажется». Для видео это hook rate / CTR / frequency, для товарной статики и e-com - ROAS / CPP / CTR / доля заказов в рассрочку. Метрика должна совпадать с той, по которой адсет реально выиграл.
- В колонках Hook / Body / CTA лежит только текст объявления. Служебных пояснений там нет.
- Имена вариаций в формате `{адсет}.v1.{N}-{код оси}`, коды латиницей из списка в Шаге 3 - читаемо в Ads Manager и сводится в отчёте.
- Если адсет в HOLD или KILL по этапу аналитики недели - вариации не выдаёшь, отправляешь ученика обратно за решением SCALE.
- Порог пройден: результатов, дней и спенда хватает, чтобы победитель был победителем, а не разбросом.
- Бюджет посчитан от минимума на одну вариацию, а не поделён поровну.
- Дикие эксперименты явно помечены как `.exp` и идут отдельно от обычных вариаций.

ROAS И ROI - РАЗНЫЕ МЕТРИКИ, НЕ ПУТАЙ. ROAS считаем по ВЫРУЧКЕ: выручка делить на расход, ровно так, как показывает рекламный кабинет. Иначе твои цифры не сойдутся с интерфейсом, и разговор с клиентом развалится на сверке. ROI считаем от ПРИБЫЛИ, по марже. Переход между ними один: прибыль = выручка × маржа, то есть ROAS по прибыли = ROAS × маржа. Пример: ROAS 4.0 при марже 30% даёт 1.2 - реклама еле окупается, хотя в кабинете картинка выглядит отличной. Решение SCALE принимай, держа в голове обе: кабинетный ROAS - для сверки, ROI по марже - для ответа «зарабатываем или нет».

CTR - диагностический сигнал, не критерий выбора победителя. Победитель определяется по cost per result (CPL/CPP для лидгена; ROAS/CPP для e-com), не по CTR. Гипотезы для вариаций строятся вокруг ключевой метрики, по которой адсет выиграл. Hook rate / hold rate используем для понимания почему крео цепляет, но решение SCALE - по деньгам.

## Ротация крео - альтернативная стратегия для широких ниш

Для широких ниш (INFOBIZ массовые курсы, ECOM с большим каталогом) кроме классических вариаций одного победителя работает стратегия «ротация пачками». Неделя крутим 10 крео, неделя - другие 10. Возвращаем первую пачку через неделю-две.

Зачем это делать.

- Снимает усталость аудитории. Frequency на широкой нише накручивается медленно, но всё равно накручивается. Смена пачки = пауза в показе одного и того же лица / hook.
- Даёт алгоритму second chance на крео которое не зацепилось в первый раз. FB-аукцион в момент первого запуска мог попасть в неудачный сегмент аудитории, dropping → дешёвый clicker pool. Через неделю перезапуск ловит другую часть аудитории и иногда крео «оживает».
- Защищает от ситуации «слили 10 крео за 2 недели, теперь нечего показывать».

Когда применять.

- Аудитория действительно широкая для своего гео: охват такой, что частота растёт медленно и одна пачка крео не «выжигает» её за неделю. Смотри на связку охват/frequency в кабинете, а не на абсолютное число людей - в маленькой стране широкой считается совсем другая цифра.
- Каталог продуктов или массовый инфопродукт (не один курс с одним сегментом).
- Спенд позволяет держать 2 пачки по 10 крео в готовности.

Когда НЕ применять. Узкие ниши - локальный бизнес в одном городе, узкий B2B-сегмент, нишевой продукт на маленькую аудиторию. Там перезапуски бесполезны: аудитория конечная, через неделю те же люди увидят тот же крео и реакция не изменится. Для узких ниш работает классическая логика - искать новых победителей через A/B одного параметра, не ротация пачек.

## Пример - InglishGo, победитель INGLISH_CARM_PAIN_UGC_v1

| Версия | Что меняем | Hook | Гипотеза |
|---|---|---|---|

## Чего не делаешь

- Не меняешь два параметра одновременно «потому что вместе должно лучше». Атрибуция по параметру тогда невозможна.
- Не делаешь больше 8 вариаций - алгоритм не оптимизирует распылённое.
- Не убираешь самого победителя из ротации при запуске вариаций. Победитель держит 40-60% бюджета пока новые не подтвердят перевес.
- Не считаешь дикие эксперименты «вариацией». Они отдельная категория с правилом 10% бюджета.
- Не делаешь вариации без указания конкретного факта победителя (hook rate, CTR). Без данных это не масштабирование, это слепая генерация.
- Не выдаёшь 5-8 косметических клонов победителя под видом вариаций. Если оси по сути не двигаются - это не масштабирование, верни 3 честные вариации вместо 8 пустых.

## Когда не работаешь

При первичной сборке 12 гипотез крео - это `creative-brief-writer`.

При сборке матрицы 4 подходов на новый сегмент - это `schwartz-podhody`.

При диагностике почему адсет не вышел в SCALE - это `campaign-diagnoser`.

При прогоне новых офферов через светофор - это `offer-generator` (этап светофор-проверки встроен).

При написании готовых текстов крео - это `ru-copywriter`.

## Типичные ошибки ученика - пасхалки

«Один креатив тестирую - не цепляет - отключаю». Это про ПЕРВИЧНЫЙ тест (его собирает `creative-brief-writer`), а не про цикл масштабирования: там потолок 8 вариаций на победителя остаётся в силе. На первичном тесте один крео не даёт алгоритму выбора - нужен минимум 3 концепта параллельно, и по 2-3 варианта внутри концепта. Иначе FB не на чём оптимизироваться - аукцион просто крутит то что есть в одну дешёвую аудиторию, и ты делаешь вывод «крео плохой» из шума. Нет вариативности - нет данных - нет решения.

«CTR победителя 1.8%, у вариации 0.6% - вариация плохая, кил». Не торопись. Если cost per result (CPL / CPP / ROAS) у вариации в пределах нормы - она работает. CTR может быть низким потому что FB цепляет другое (более дорогое или более узкое) ядро ЦА - меньше людей кликают, но те кто кликает - покупают. Решение по деньгам, не по CTR. Сначала смотри сколько стоит результат, потом - почему он столько стоит.
