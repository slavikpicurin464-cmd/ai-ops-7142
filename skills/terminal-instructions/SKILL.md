description: Используй автоматически всегда когда выдаёшь команды для терминала (bash, zsh, shell), команды git, npm, brew, pip, любые команды для запуска в Terminal.app на Mac или в командной строке Windows. Триггеры - выдача любых shell-команд, инструкции по установке через CLI, команды для git push/pull/commit, команды для запуска скриптов, инструкции по работе с файлами через терминал. Скил заставляет тебя явно помечать какие команды выполнять построчно а какие можно одним блоком, и предупреждать об интерактивных запросах (пароли, Y/N, выбор опций).
---

Ты выдаёшь команды для терминала чётко и понятно для человека который не разработчик. Главное правило - не давай ученику свалиться на середине последовательности команд потому что одна из них требует ввода или ждёт ответа другой.

СНАЧАЛА ОПРЕДЕЛИ СИСТЕМУ

До первой команды выясни, Mac у ученика или Windows. Не знаешь - спроси одной строкой. Команды из разных систем не взаимозаменяемы: `brew`, `sudo` и пути вида `~/Documents` на Windows не работают вообще, и ученик получит ошибку на первом же шаге.

- **Mac.** Терминал (Terminal.app) или iTerm. Установка пакетов - `brew`. Права администратора - `sudo`. Пути - `~/Documents/...`, домашняя папка обозначается `~`.
- **Windows.** PowerShell (Win+X → Terminal или Windows PowerShell), не старый cmd. Установка пакетов - `winget install`. Права администратора - не `sudo`, а запуск самого PowerShell от имени администратора (правый клик по значку → «Запуск от имени администратора»). Пути - `C:\Users\Имя\Documents\...`, домашняя папка обозначается `$HOME`.

Общее для обеих систем: команды `git`, `npm`, `python`, `node` пишутся одинаково. Различаются установка, права и пути.

ПРАВИЛО ПОСТРОЧНО ИЛИ БЛОКОМ

ДЕФОЛТ - давай команды одним блоком. Только если есть реальные причины разделять - дроби на отдельные строки. Не перестраховывайся.

Можно одним блоком (это нормальный случай) -
- Обычная последовательность типа `cd → git add → git commit → git push`
- Команды которые независимы или просто идут друг за другом
- Несколько установочных команд через `&&` или подряд

Дробить на построчно только если -
- Команда может попросить пароль, токен или passphrase. Такую команду выносишь ПОСЛЕДНЕЙ строкой блока, а всё, что должно идти после неё, отдаёшь отдельным блоком после отчёта ученика. Строки, вставленные следом за запросом пароля, уходят в поле пароля как его часть - ломается вся последовательность, и понять это по экрану нельзя
- Результат одной команды нужно ВРУЧНУЮ скопировать в следующую (например `gh repo create` выдаёт URL, потом ты сам подставляешь его в `git remote add`)
- Между командами надо что-то проверить ГЛАЗАМИ перед следующей (например проверить что репо создан в браузере)
- Команды конфликтные - если одна упадёт, остальные навредят (типа `rm -rf` после неудачной проверки)
- Это интерактивные wizards которые блокируют терминал на ввод (`gh auth login` с выбором опций в браузере)

Если есть сомнения - давай блоком. Большинство случаев именно блоком.

КАК ПОМЕЧАТЬ В ТЕКСТЕ

Когда выдаёшь блок команд который можно одним пуском - пишешь сверху -

«Запусти всё одним блоком, скопируй разом -»

Когда выдаёшь команды построчно - пишешь сверху -

«Выполняй построчно. После каждой команды вставь мне сюда последние строки вывода терминала - без них следующую команду я не дам.»

ВЫВОД ТЕРМИНАЛА - ПРЕДУПРЕЖДАЮЩИЙ ГЕЙТ. Проси вывод после каждой команды. Не показал - работу не стопори, но и не считай шаг успешным: пиши строкой «шаг N не подтверждён, дальше идём вслепую» и потом не ссылайся на него как на сделанный. «Ок, сделал» - это не вывод.

Полный стоп только в двух случаях: следующая команда зависит от результата предыдущей (надо подставить URL, имя ветки, путь) либо она опасна при неудаче предыдущей (удаление, публикация, перезапись). Там без вывода не идёшь.

Вывод пришёл с ошибкой - сначала чинишь её, потом дальше.

Если в блоке есть интерактивные команды - предупреди что произойдёт -

«Команда `git push` может попросить логин и пароль. Username - твой логин GitHub. Password - это НЕ пароль от GitHub, а Personal Access Token. Если терминал ничего не спросит - значит токен уже сохранён в Keychain, проходим дальше.»

«Команда `brew install gh` ставится без вопросов. Но при самой первой установке Homebrew может попросить пароль от Mac для Command Line Tools. Пароль вводится вслепую - символы на экране не появляются, это нормально, набирай и жми Enter.»

«Команда `sudo` попросит пароль от Mac. Это пароль которым ты разлочиваешь компьютер. Он тоже вводится вслепую.»

ПРИМЕРЫ ПРАВИЛЬНОЙ ВЫДАЧИ

Пример 1. Простой коммит - можно блоком, пуш отдельно.

«ЗАМЕНИ `ПУТЬ-К-ПАПКЕ` на путь к своей папке - проще всего перетащить папку из Finder прямо в окно терминала, путь подставится сам. ЗАМЕНИ `текст сообщения` на то, что ты поменял. Дальше запусти блок целиком -

```
cd ПУТЬ-К-ПАПКЕ
git status
git add .
git commit -m "текст сообщения"
```

Покажи мне, что ответил терминал. Если всё хорошо - следующей строкой отдельно запустишь `git push`: он может попросить логин и токен, поэтому идёт отдельно от остальных команд.»

Пример 2. Установка GitHub CLI - построчно.

«Выполняй построчно. После каждой команды смотри что отвечает терминал -

`brew install gh` - установка займёт 30-60 секунд, вопросов не задаёт. При самой первой установке может попросить пароль от Mac - вводится вслепую.

`gh auth login` - запустит интерактивную авторизацию. Выберешь GitHub.com → HTTPS → Y (auth Git с твоими credentials) → Login with web browser. Откроется браузер.

Перед следующей командой запусти `ls` и посмотри, что лежит в папке. Если там данные клиента, выгрузки, доступы или ключи - в публичный репозиторий это выкладывать нельзя.

`gh repo create my-repo --private --source=. --push` - создаст ЗАКРЫТЫЙ репозиторий и запушит содержимое папки. `--private` стоит по умолчанию осознанно: `--public` открывает содержимое папки всему интернету, и отката у этого нет. Меняй на `--public` только если точно понимаешь, что выкладываешь.»

Пример 3. Создание нового репо через сайт + push - построчно с проверкой.

«Сначала создай репо на github.com через сайт (это руками в браузере, не в терминале). После этого вернись в терминал и выполняй построчно -

`cd ПУТЬ-К-ПАПКЕ` и следом `git status` - проверяем, что папка вообще репозиторий. Если ответ `fatal: not a git repository` - сначала выполни `git init`, иначе все команды ниже упадут.

`git remote remove origin` - убирает старый (некорректный) remote если он был. Если remote ещё не настроен - будет ошибка fatal: No such remote 'origin', это нормально, идём дальше.

`git remote add origin https://github.com/ТВОЙ-ЛОГИН/имя-репо.git` - ВАЖНО. Подставь свой реальный логин GitHub, не пиши буквально ТВОЙ-ЛОГИН.

`git push -u origin main` - запустит первый пуш. Может попросить логин и токен один раз. После этого работает молча. Если ответит `src refspec main does not match any` - посмотри `git branch` и подставь то имя ветки, которое покажет git (часто это `master`).»

КАК НАЗЫВАТЬ PLACEHOLDER В КОМАНДАХ

Если в команде есть кусок который пользователь должен заменить на своё (логин, имя репо, путь) - явно помечай его и предупреждай что НЕ копировать дословно. Иначе пользователь скопирует «ТВОЙ-ЛОГИН» буквально и команда не сработает.

Хорошо -
«В команде ниже ЗАМЕНИ `ТВОЙ-ЛОГИН` на свой реальный логин GitHub (например `ivanov-target`). Не копируй дословно слово ТВОЙ-ЛОГИН -

`git remote add origin https://github.com/ТВОЙ-ЛОГИН/repo.git`»

Плохо -
«Выполни -

`git remote add origin https://github.com/ТВОЙ-ЛОГИН/repo.git`»

ЧТО ДЕЛАТЬ ЕСЛИ ОШИБКА

Когда даёшь команды - добавляй короткую подсказку что делать если что-то пошло не так. Не обширную, а одну строку с типичной ошибкой.

«Если выдаст `command not found: gh` - значит GitHub CLI не установлен, поставь через `brew install gh` сначала.»

«Если `permission denied` - НЕ добавляй `sudo` вслепую. Сначала проверь, туда ли ты смотришь: `ls -la` в текущей папке. У новичка это почти всегда не тот путь или чужие права, а не нехватка прав администратора. `sudo` уместен только для системных пакетов. Под `sudo` никогда не запускай `git`, `npm` и `python` в своей рабочей папке: они создадут файлы от имени root, после чего обычные команды перестанут работать, а починить это самому уже трудно.»

«Если `Repository not found` - проверь что в команде твой логин GitHub а не плейсхолдер.»

«Если `*** Please tell me who you are` при `git commit` - у git не заданы имя и почта. Выполни две команды, потом повтори коммит -

```
git config --global user.name "Имя Фамилия"
git config --global user.email "почта@example.com"
```
»

«Если `command not found: git` или `Failed to clone marketplace repository` - на компьютере нет git, а он нужен для клонирования. На Mac: `xcode-select --install` либо `brew install git`. На Windows: поставить Git for Windows с git-scm.com. После установки ПОЛНОСТЬЮ закрой и открой заново и приложение, и терминал - без перезапуска установленный git не увидят. Проверка: `git --version` должна напечатать номер версии.»

ЧЕГО НЕ ДЕЛАТЬ

Не давай 5-7 команд блоком если одна из них может попросить пароль. Пользователь скопирует блок целиком, первая команда попросит пароль, остальные 4-6 команд уйдут в строку запроса пароля как часть пароля - сломается всё. Команду с паролем выносишь последней строкой, остальное - следующим блоком.

Не давай команду, которая делает содержимое папки публичным (`gh repo create ... --public`, публикация на хостинг), без предупреждения и без шага «посмотри `ls`, что в папке». В рабочей папке таргетолога лежат выгрузки, доступы и данные клиентов.

Не давай команду с `rm -rf` или `sudo rm` без явного предупреждения «эта команда удаляет данные, дважды проверь путь перед запуском».

Не предполагай что у пользователя есть установленное окружение (git / gh / brew / node / python). Если используешь команду которая требует установки - сначала проверь, либо дай команду на установку первой.

Не используй малопонятные алиасы которые могут не работать у пользователя. Используй полные команды.

КОГДА ИСПОЛЬЗОВАТЬ ДРУГИЕ СКИЛЫ

Этот скил включается автоматически при выдаче любых терминальных команд. Не нужно явно вызывать - просто помечай команды правильно когда выдаёшь.

Если задача не про терминал а про что-то другое - этот скил не подгружается.
